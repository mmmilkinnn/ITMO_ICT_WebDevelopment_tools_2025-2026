    Лабораторная Работа 2¶

    Тема¶

    Потоки, процессы и асинхронность в Python.

    Выполнила: Маркозубова Анастасия

    Цель работы¶

    Целью лабораторной работы является изучение различий между threading, multiprocessing и асинхронным подходом в Python. Работа помогает понять, где удобнее использовать потоки, где процессы, а где асинхронность.

    В лабораторной работе реализованы две задачи:

    • подсчет суммы чисел от 1 до 10_000_000_000_000;
    • параллельный парсинг веб-страниц с сохранением результатов в базу данных.

    Использованные технологии¶

    • Python 3.10+
    • threading
    • multiprocessing
    • asyncio
    • aiohttp
    • SQLAlchemy
    • PostgreSQL
    • HTMLParser

    Задача 1. Подсчет суммы чисел¶

    В первой задаче нужно было написать три программы, которые считают сумму всех чисел от 1 до 10_000_000_000_000.

    Для всех трех подходов используется функция calculate_sum().

    Диапазон чисел делится на несколько частей. Каждая подзадача считает сумму своего диапазона, после чего частичные суммы складываются.

    Сумма поддиапазона считается по формуле арифметической прогрессии:

    (start + end) * (end - start + 1) // 2

    Это сделано потому, что прямой цикл до 10_000_000_000_000 выполнялся бы слишком долго.

    Threading¶

    Файл:

    task1/threading_sum.py

    В программе используется модуль threading. Для каждого поддиапазона создается отдельный поток. Потоки находятся внутри одного процесса.

    Потоки хорошо подходят для задач ввода-вывода, но для тяжелых вычислений в Python они часто ограничены GIL.

    Multiprocessing¶

    Файл:

    task1/multiprocessing_sum.py

    В программе используется модуль multiprocessing. Поддиапазоны передаются в пул процессов через Pool.starmap().

    Процессы подходят для вычислительных задач лучше потоков, потому что каждый процесс имеет свой интерпретатор Python и может выполняться на отдельном ядре процессора.

    Asyncio¶

    Файл:

    task1/async_sum.py

    В программе используется async/await и модуль asyncio. Для каждого поддиапазона создается асинхронная задача, а результаты собираются через asyncio.gather().

    Асинхронность особенно полезна для задач ожидания: сетевых запросов, таймеров, работы с асинхронными API. Для чистых вычислений она не дает настоящего параллелизма на нескольких ядрах.

    Задача 2. Параллельный парсинг веб-страниц¶

    Во второй задаче нужно было написать три программы для параллельного парсинга веб-страниц и сохранения результата в базу данных.

    Каждая программа содержит функцию parse_and_save(url), которая:

    • загружает HTML-страницу по URL;
    • извлекает заголовок из тега <title>;
    • сохраняет результат в базу данных;
    • выводит результат на экран.

    База данных для task2¶

    Для второй лабораторной используется отдельная база:

    hackathon_lab2

    В ней создается такая же схема, как в первой лабораторной работе. Основная таблица, которую заполняет парсер:

    hackathons

    Это подходит по предметной области: первая лабораторная реализует систему проведения хакатонов, а во второй задаче парсятся страницы с хакатонами, соревнованиями и developer events.

    Сопоставление данных:

    Поле таблицы hackathons Что сохраняется
    title заголовок HTML-страницы
    description URL источника и подход парсинга
    start_date дата запуска парсера
    end_date дата запуска + 7 дней
    status parsed
    organizer_id служебный пользователь-организатор

    Служебный организатор имеет email:

    lab2-hackathon-parser@example.com

    Он нужен только потому, что в схеме lab1 поле organizer_id является обязательным.

    В нем находятся:

    Threading parser¶

    Файл:

    task2/threading_parser.py

    Программа делит список URL на части и запускает несколько потоков. Пока один поток ожидает ответ от сайта, другой может выполнять свой запрос.

    Multiprocessing parser¶

    Файл:

    task2/multiprocessing_parser.py

    Программа делит URL между несколькими процессами. Каждый процесс обрабатывает свою часть списка и сохраняет результаты в базу.

    Этот подход работает, но для сетевого парсинга может иметь больше накладных расходов, чем потоки или асинхронность.

    Async parser¶

    Файл:

    task2/async_parser.py

    Программа использует asyncio и aiohttp. Один event loop управляет несколькими HTTP-запросами.

    Для сетевого парсинга это обычно самый удобный и легкий подход, потому что не нужно создавать отдельный поток или процесс на каждый запрос.

    Как запустить¶

    Создать базу данных¶

    psql -U postgres

    CREATE DATABASE hackathon_lab2;
\q

    Если база уже существует, повторно создавать ее не нужно.

    Посмотреть данные в базе¶

    psql -U postgres -d hackathon_lab2

    SELECT id, title, description, status, organizer_id
FROM hackathons
WHERE status = 'parsed'
ORDER BY id;

    Сравнение подходов¶

    threading удобен для задач, где программа часто ждет: сетевые запросы, работа с файлами, обращения к внешним сервисам.

    multiprocessing лучше подходит для тяжелых вычислений, потому что процессы могут выполняться на разных ядрах процессора.

    asyncio хорошо подходит для большого количества операций ожидания. В задаче парсинга он показывает себя особенно хорошо, потому что HTTP-запросы большую часть времени ждут ответа от сервера.

    Вывод¶

    В ходе лабораторной работы были реализованы программы на threading, multiprocessing и asyncio. На вычислительной задаче видно, что процессы больше подходят для CPU-bound задач, а потоки и асинхронность полезнее для I/O-bound задач.

    Во второй задаче был реализован параллельный парсинг веб-страниц с сохранением заголовков в PostgreSQL-базу hackathon_lab2. Для сетевых запросов наиболее удобным оказался асинхронный подход через asyncio и aiohttp.
