# Лабораторная Работа 1

## Тема

Создание системы для проведения хакатонов.

> Выполнила: Маркозубова Анастасия

## Цель работы

Целью лабораторной работы является разработка полноценного серверного приложения на FastAPI с использованием PostgreSQL, ORM SQLAlchemy, миграций Alembic и пользовательского функционала на основе JWT.

## Использованные технологии

- Python 3.10+
- FastAPI
- PostgreSQL
- SQLAlchemy
- Alembic
- Pydantic
- Uvicorn

## Структура проекта

Проект разделен на несколько логических частей:

- `app/main.py` — точка входа в приложение
- `app/core/` — конфигурация и безопасность
- `app/db/` — подключение к базе данных и регистрация моделей
- `app/models/` — ORM-модели SQLAlchemy
- `app/schemas/` — Pydantic-схемы запросов и ответов
- `app/api/routes/` — маршруты API
- `migrations/` — миграции Alembic

Такая структура делает код понятным, удобным для поддержки и разделяет бизнес-логику по ответственностям.

## Предметная область

Приложение реализует систему для проведения хакатонов. В системе можно:

- регистрировать пользователей;
- разделять пользователей на организаторов и обычных участников;
- создавать хакатоны;
- регистрироваться на хакатоны;
- создавать команды;
- присоединяться к командам;
- публиковать задачи;
- отправлять решения;
- оценивать решения.

## Модель данных

В проекте реализованы следующие таблицы:

1. `users`
2. `hackathons`
3. `hackathon_registrations`
4. `teams`
5. `team_memberships`
6. `tasks`
7. `submissions`
8. `reviews`

### Связи one-to-many

- один организатор может создать много хакатонов;
- один хакатон может содержать много задач;
- один хакатон может содержать много команд;
- одна задача может иметь много отправленных решений;
- одно решение может иметь много оценок.

### Связи many-to-many

- пользователь и хакатон связаны через таблицу `hackathon_registrations`;
- пользователь и команда связаны через таблицу `team_memberships`.

### Ассоциативные сущности с дополнительными полями

#### `hackathon_registrations`

Хранит:

- ссылку на пользователя;
- ссылку на хакатон;
- `status` — статус регистрации;
- `registered_at` — дату регистрации.

#### `team_memberships`

Хранит:

- ссылку на пользователя;
- ссылку на команду;
- `role` — роль участника команды;
- `joined_at` — дату вступления.

## Пользовательский функционал

В проекте реализованы:

- регистрация пользователя;
- авторизация;
- генерация JWT-токена;
- аутентификация по JWT;
- хэширование пароля;

- получение списка пользователей;
- смена пароля.

## Безопасность и ограничения доступа

### Организатор может

- создавать хакатоны;
- редактировать и удалять только свои хакатоны;
- создавать задачи только для своих хакатонов;
- изменять и удалять задачи только своих хакатонов;
- менять статусы регистраций только в своих хакатонах;
- создавать оценки только для решений в своих хакатонах;
- изменять и удалять только свои оценки.

### Обычный пользователь может

- регистрироваться;
- входить в систему;
- получать свой профиль;
- регистрироваться на хакатоны;
- создавать команды;
- вступать в команды;
- отправлять решения.

### Дополнительные ограничения

- пользователь не может зарегистрироваться дважды на один и тот же хакатон;
- пользователь не может вступить в одну и ту же команду дважды;
- пользователь может отправить решение только от своей команды;
- команда и задача должны относиться к одному и тому же хакатону;
- email пользователя уникален;
- номер телефона пользователя уникален.

## Вложенные GET-запросы

### `GET /api/hackathons/{hackathon_id}`

Возвращает:

- данные хакатона;
- организатора;
- регистрации;
- команды;
- задачи.

Возвращает:

- данные команды;
- создателя команды;
- участников команды с ролями.

### `GET /api/submissions/{submission_id}`

Возвращает:

- данные отправленного решения;
- задачу;
- команду;
- автора отправки;
- оценки.

## Подключение к базе данных

Подключение выполняется в файле `app/db/session.py` через `create_engine` и `sessionmaker`.

Используется PostgreSQL.

Пример строки подключения:

```python
DATABASE_URL = "postgresql+psycopg://postgres:1234@localhost:5432/hackathon_lab1"
```

## Миграции

Для управления схемой базы данных используется Alembic.

### Основные команды

Создание миграции:

```bash
alembic revision --autogenerate -m "initial schema"
```

Применение миграции:

```bash
alembic upgrade head
```
